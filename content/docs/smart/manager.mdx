## Default Config

Smart's core configuration lives at `rustyconnector/smart/config.yml`:

```yml
# Name of the Haze database used to persist the registry of live smart servers.
database: "default"
```

Make sure a Haze driver (MySQL, Postgres, ...) is installed and the database is registered under this name.

## Providers Configuration

Each provider has its own config file at `rustyconnector/smart/providers/<id>.yml`:

```yml
providerId: "pterodactyl"
includedFamilies:
  - "lobby"
  - "bedwars"
excludedFamilies:
  - "auth"
maxProcesses: 5
priority: 10
```

The Smart core tests providers by descending priority.
**Let's break this down!**

### Provider id
The provider's name **is the name of its config file**: `pterodactyl.yml` → provider `pterodactyl`, `node-1-west.yml` → provider `node-1-west`. The file also declares `providerId` inside, which must match the file name and the id the provider module registers itself with. The id is the technical key used everywhere (registry, `smart.<providerId>` metadata block, env overrides like `SMART_PTERODACTYL_EGG`).

### Included Families
This is a list of families that the provider can handle. If a family is not in this list, the provider will not be used to create servers for that family.
If this list is empty, the provider will be used for all families.

### Excluded Families
This is a list of families that the provider cannot handle. If a family is in this list, the provider will not be used to create servers for that family.
If a family is in both the included and excluded list, the excluded list takes precedence.

### Max Processes
This is the maximum number of concurrent processes that the provider can handle. If the provider is already handling the maximum number of processes, it will not be used to create new servers.
One server counts for one process.

### Priority
When several providers can serve the same family, the one with the **highest priority** is tested first. If it has no capacity left, the next one is tried. Defaults to `0`.

### Reusing a provider multiple times
The same provider type can be registered several times — just add more files with distinct names, e.g. `node-1-west.yml` and `node-1-east.yml`, each declaring its own `providerId` matching the file name. Use `priority` to control which instance is preferred.

### RAM Amount
RAM is **not** configured per provider anymore. Each family declares how much memory its smart servers need via the `smart.memory` metadata key. See all of Smart's metadata keys [here](./metadata.mdx).
