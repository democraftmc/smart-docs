## Smart Metadata Keys

Smart uses metadata keys to store and retrieve various types of information related to families. Here is a list of commonly used metadata keys in Smart:

- `smart.memory` sets the shared RAM default in whole MB (1 MB = 1,000,000 bytes).
- `smart.cpu` sets the shared CPU default in cores and accepts fractions.
- `smart.<providerId>` contains workload settings and overrides for that provider instance. See [provider documentation](/docs/providers/official).

The default ruty metadata string looks like this:

To set a metadata key for a family, add it to the metadata object. For example, to set the `smart.memory` key to `2048` for a family, you would do the following:

    ```yml
      hardCap: 40
      smart:
    ```

    ```json
      "softCap": 30,
      "hardCap": 40,

    }
    ```

## Environment Variables

### Path-based overrides (recommended)

Every metadata path can be overridden by an environment variable **without touching the config**. The variable name is derived from the dotted path: uppercase it, replace dots with underscores, strip the leading `smart.` root, and prefix with `SMART_`.

| Metadata path | Env override |
| --- | --- |
| `smart.memory` | `SMART_MEMORY` |
| `smart.pterodactyl.egg` | `SMART_PTERODACTYL_EGG` |
| `smart.docker.env.EULA` | `SMART_DOCKER_ENV_EULA` |

The env var wins over the config value; the config value acts as the default. Numeric/boolean defaults are coerced from the env string when possible.

```bash
export SMART_DOCKER_ENV_EULA="TRUE"
export SMART_MEMORY=4096
```

Set connection credentials in the proxy environment using each provider’s `RC_<ID>_TOKEN` setting. Use `smart.<providerId>.env` for variables passed to the workload.

## Providers Metadata Keys

Providers may also use metadata keys to store and retrieve information related to their own configuration. 
These keys are specific to each provider and are documented in the provider's documentation.
They are usually store in an object with the provider id as key inside the `smart` field.

Here is an example with the pterodactyl provider:
